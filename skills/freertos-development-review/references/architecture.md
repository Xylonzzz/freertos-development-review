# 任务、数据与资源边界

来源映射：原文第 1–10、23–29、30、34–36、48–54、62–65 节。

## 先识别实际结构

从启动入口、任务创建、RTOS 对象、外设回调和活动构建文件建立模型。区分生成文件、自定义源码、历史副本和未参与编译的实验代码。对目录层次的判断以调用和依赖关系为准。

跨层审阅关注：业务决策、任务编排、公共服务、驱动和硬件映射分别由谁负责；纯算法是否可独立于 HAL/RTOS/全局业务状态运行。不要把教程画出的 Services → Tasks 当作所有工程必须遵循的调用方向。

任务表按需列出：任务、触发/周期、优先级、最大执行与阻塞时间、输入/输出、独占资源和异常处理。任务内部的多个周期活动不等于多个独立调度任务；截止时间、执行时间和共享资源才是优先级判断依据。

## 交接方式的选择

| 需求 | 适合的机制 | 审阅重点 |
|---|---|---|
| 按顺序处理命令、完整报文、保存请求 | 有界 Queue | 结构大小、容量、顺序、满队列策略、消费速率 |
| 消费最新完整测量或整机状态 | 快照/受控复制 | 同步、完整批次、发布序号、数据质量和时间语义 |
| 等待多个就绪条件、锁存合并故障 | Event Flags/Group | 置位与清除竞态、合并语义、错误返回、超时 |
| 某个任务等待 DMA 完成等单目标事件 | Task Notification 或对应封装 | 接收对象、计数/位语义、丢失、超时与生命周期 |
| 多任务短时访问同一资源 | Mutex | 是否真共享、持锁时间、锁顺序、失败释放路径 |
| 资源可串行委派 | 所有者任务 + 请求/结果交接 | 请求与完成区别、结果消费者、取消和积压 |

不同机制不必统一。测量快照不等于事件队列；事件位合并不等于保留每一条故障详情。判断是否满足业务语义后再建议替换。

## 同步与生命周期

- 检查获取锁的返回值；失败后不能继续访问受保护数据，也不能释放未持有的锁。读写两侧必须遵循同一协议，窄接口本身不提供同步。
- 核对复合结构复制、读改写及多字段一致性。`volatile` 不代替同步；单字段可能原子不代表整份快照原子。
- 识别谁推进发布序号。把工作结构完整复制到公开结构时，不能意外覆盖公开序号，使消费者误判没有更新。
- Queue 复制的是配置的消息字节数。消息中含指针时，缓冲区生命周期、独占、归还和失败路径需要另行闭合；局部地址或 DMA 即将覆盖的地址不能当作完整消息副本。
- DMA缓冲区状态至少区分空闲、DMA持有、待处理、消费者持有。双缓冲仍需证明消费者能及时释放；队列满和消费者变慢时要有策略。
- 识别资源所有者的全部入口和实际跨任务调用。统一锁顺序，并追踪锁嵌套、临界区内等待、锁内日志/Flash以及优先级继承的实际封装实现。

## ISR 和 Timer Callback

追踪“ISR → 完整消息/事件 → 任务解析 → 控制决策”，检查 ISR 是否进行耗时日志、Flash、业务状态迁移或阻塞操作。

区分 FreeRTOS 原生 API 与 CMSIS 等封装的上下文要求：原生 API 需要正确的 FromISR 版本；封装可能在内部区分 ISR，须检查其实现和零等待要求。

对于Cortex-M端口，核对 NVIC 分组、实际中断优先级、RTOS 系统调用门限与异常使用的 API；较小优先级数字表示更高紧迫度。其他端口按其实际中断规范核对，不能把所有中断都默认允许调用 RTOS。Task 优先级与 NVIC 优先级是不同体系。软件 Timer Callback 所在服务任务也不能被耗时操作或等待堵住。

## 时间与资源预算

- 对比延迟相对上次完成时间与绝对截止时间调度，确认执行时间是否计入周期；超期时是补跑、跳过还是主动让出 CPU，要符合业务期限。
- 单次 timeout、重试次数、整项操作预算、持锁预算和状态总停留时间分别核查。长底层调用会阻止上层状态机检查超时。
- 区分 `HAL_GetTick()` 的毫秒与内核 Tick，核对频率、回绕算术、转换及时间源启动阶段。不能只因当前都为 1ms 就混用而不声明。
- 栈创建参数、CMSIS `stack_size` 与 FreeRTOS 高水位的单位应按封装/端口核实。分别报告启动动态分配、运行动态分配、静态缓存与内存峰值。
- 优先级、栈和 Queue 参数同时对照生成配置、源码及构建覆盖定义。配置冲突是漂移风险；先确定预期，不直接把其中一份覆盖成另一份。

先修接口和行为边界，再按实际需要整理目录。框架迁移不得因示例推荐就替换已有 CMSIS 版本、消息协议或任务集合。
