# 验证与报告

来源映射：原文第 45–47、57–61、68–71 节。

## 验证层级

| 证据 | 可以证明 | 不能据此宣称 |
|---|---|---|
| 活动源码与配置检查 | 可定位的边界、调用、所有权、配置冲突 | 固件已运行、实测期限满足 |
| 主机单元测试/故障模型 | 算法、状态转移、错误返回、特定故障逻辑 | 真实外设、RTOS调度和电气行为正确 |
| 固件构建与静态分析 | 当前配置可构建、特定诊断结果 | 功能和硬件安全验收通过 |
| 仿真/目标板运行记录 | 实际运行在给定场景下的结果 | 未覆盖条件及完整真实系统验收 |
| 真实硬件验收 | 已执行条件下的系统行为 | 其他条件、额定性能和长期可靠性 |

仅按任务需要进入相应层级。只读审阅可执行合适的已有静态检查，但无需为了审阅运行所有构建、引入工具链、重写测试或操作硬件。

开发与修复按本次变更验证：算法/状态机测试、接口失败注入、实际工程构建及必要的静态检查。任务、Queue或初始化改变时还要核对资源配置与生产消费连接；主机模型通过不能代替当前配置的固件构建。

## 最小异常场景

每个用例写清：起始状态 → 故障触发 → 预期检测 → 预期动作/记录 → 期限 → 观察变量 → 通过判据。找不到可控入口或观测量时，明确需先补什么测试接点。

| 路径 | 有价值的异常输入 | 核心判据 |
|---|---|---|
| ADC/传感器 | 启动失败、持续超时、首次PEC失败、成功后连续失败、无效通道 | 有界返回；无效值/旧值不被伪装成新成功样本 |
| 输入/组包 | 短帧、乱序、缺片、超时、非法范围、字段冲突、非法状态命令 | 完整校验后才生效；失败不应用半份参数 |
| Queue/快照 | 满队列、无效对象、锁超时、消费延迟、复制中途切换 | 关键故障可观察且有处置；无混合批次/生命周期错误 |
| 控制/状态机 | 错误状态收到启动、反馈不符、状态永不完成 | 保持允许的输出；非法转移拒绝；超时路径可达 |
| Watchdog | 周期任务停止进展、事件任务合法空闲、事件处理超时、监督者停止 | 合法空闲不误判；关键失效按期限检测；复位后原因可查 |
| Flash | 擦除/编程/校验/提交阶段失败或中断、两份均损坏、旧格式 | 启动只接受完整有效版本或规定缺省，能识别失败 |

只对真实需求给出合理判据，不虚构固定安全时间、温度/电压阈值或自动恢复条件。Tick回绕、整数端点、NaN/Inf和查表边界适合用可控的主机测试验证。

目标板上的任务卡死、拔线、复位、Flash掉电和高压测试属于实际操作，按用户授权和项目规则执行；规划用例不授权执行。较高优先级任务的死循环可能使 Monitor 得不到CPU，不能预先承诺“Monitor会先关断”；此类用例应分别验证软件监督、硬件看门狗和输出安全路径。

压力测试按产品使用场景选择持续时间、负载及故障组合。记录版本、编译模式、任务栈/堆峰值、队列积压/丢失、错误和复位次数、响应时间与数据年龄，避免固定要求所有项目做7天测试。

## 复用工程现有检查

先读取相关脚本和活动代码，确认它检查的契约仍适用，再执行。脚本失败后区分真实代码违约、生成配置漂移、脚本过期与执行环境问题。文本/正则契约通过只证明其检查条件，不能证明运行时完整性。

不为低影响、可逆的说明/命名改动建立只复述实现的测试。行为缺陷需要能够触发原失败的用例；完成本次必要检查后，只有新改动、失败或未解决疑点才扩大验证。

## 输出尺度

先给结论、影响与适用范围，再给关键证据和建议。小问题用简洁段落；全工程审阅按严重程度列发现，必要时附一张任务/交接表或小图。框架适配用“已有、需改造、暂不采用”说明取舍。

报告必须保留：

- 核查的工程/分支/配置、活动模块和取样范围。
- 已有的合理机制及需要保留的契约。
- 确定缺陷与条件性风险，附准确文件/符号证据。
- 有先后顺序的最小改进和相应验证条件。
- 已执行检查及真实结果、未执行验证与其限制。

开发交付补充实际修改文件、前后行为、关键实现取舍和集成入口。按项目需要说明风险与回退；不要把尚未实现的设计或伪代码称为已完成功能。

无证据时写“未展示/尚未核实”，不要写“没有实现”。总体结论不得覆盖未审阅模块；硬件结果也不得从静态源码推导。

## 对本 Skill 的试用

用真实请求或隔离材料试用，而不是让评估者复述本文件。开发用例检查是否选对工作模式、完成请求范围内的设计/实现、连接真实接口并验证异常路径；审阅用例检查是否沿代码发现问题、保留合理机制、区分未知条件、给出可观察判据并保持只读。格式校验不等于开发/审阅能力验证；一次试用不证明所有项目都覆盖。
