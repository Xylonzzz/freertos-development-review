# 异常路径与可靠性

来源映射：原文第 11–24、31–33、39–47、49–56、68–70 节。

对每条关键路径检查：预防 → 检测 → 隔离 → 降级 → 恢复 → 记录。既检查失败分支存在，也检查它能被执行、结果能被消费。

## 采集质量与输入

把以下概念分别检查，不让一个 `valid` 或 heartbeat 代替所有含义：

- **任务进展：** 任务是否完成了预定步骤或请求。
- **传输成功：** 外设操作、协议/PEC/CRC 是否成功。
- **测量合法：** 数值有限、在物理范围内，通道真实存在。
- **数据年龄：** 最后一次成功采样时间，而不只是最后一次发布/复制时间。
- **消费完整：** 对应同一批次，消费者确实取得并使用。

采集失败可按产品约定保留旧值，但必须暴露保留、失效和超龄状态，检查保护、均衡、算法和遥测的各自策略。通道级失败不能总由整包有效标志代替；兼容槽位、未接通道与真实通道需遵守项目拓扑契约。

检测返回值、数组查找端点、插值邻点、除零、整数转换、长度加法、NaN/Inf和非法枚举。不能用“驱动返回 OK”证明测量物理正确，也不能用“单次 HAL 等待有 timeout”证明整条采集有界。

外部输入应沿真实接收链检查：帧类型/RTR/DLC、总长度、顺序、组包超时、完整性、数值范围、字段关系、当前状态与权限。分片帧号全部到齐不等于字节全部到齐；控制参数需验证整个候选值之后再应用和持久化。CAN 链路 CRC 不代替应用层命令完整性与业务检查。

## 故障送达与输出

区分瞬时失败、可恢复错误和严重故障，以产品后果确定策略，不直接复制教程错误级别表。

检查错误上报的发送结果、满队列处理、锁存、消费、重复抑制、清除及记录。计数丢失只增加可观测性，不保证关键故障被处理。关键事件位可补充普通队列，但仍要验证置位失败、清除竞态、合并和 Control 响应。

正常运行的危险输出应遵守项目指定的所有权。ErrorTask、MonitorTask、RecoveryTask 不因名称就获得输出权限。Control 无法运行、异常上下文或内核受损时，检查独立的紧急关断/复位路径；不能只给失效的 Control 发消息。

核查上电GPIO安全电平及实际初始化顺序、正常故障处理、启动失败、RTOS对象失败、assert、Stack Overflow、malloc失败、HardFault等入口。异常处理应尽量只依赖可用的最小机制；不要在 HardFault 中假设锁、队列、堆、日志和普通 Flash 保存仍能运行。

寄存器关断命令不证明实际继电器断开。根据证据区分控制命令、反馈状态、板级电气和真实系统验收。Safe State 的内容取决于产品，避免笼统写“关闭所有输出”。

## Watchdog 与诊断

周期任务、事件任务和启动阶段采用不同进展条件：

| 类型 | 健康证据 | 误判风险 |
|---|---|---|
| 周期采集/控制 | 到期工作完成、成功数据或决策进展、超期预算 | 循环活着但输入已失效 |
| Storage等事件任务 | 空闲合法；有请求时在预算内完成并反馈 | 无请求等待被误判为卡死 |
| 诊断/日志等辅助任务 | 按其重要性检查进展、积压和资源 | 非关键故障导致不必要整体复位 |
| 初始化/恢复阶段 | 阶段进度、阶段预算和失败出口 | 超时时间未覆盖合法启动流程 |

检查监督者是否读到一致状态，是否把资源检查、自检结果纳入最终健康决策；仅在函数调用前保存 `healthy`，随后忽略新的检查结果，不能形成完整喂狗条件。

IWDG喂狗应由明确健康条件约束，并考虑监督任务自身卡死、较高优先级任务不让出CPU、中断长时间关闭。超时窗口要同时满足合法最坏执行/阻塞时间与产品故障响应期限，不固定为教程示例值。

已有Stack/Heap/Queue水位、drop计数、deadline miss和耗时统计值得保留；区分统计、报警、保护和复位各自是否实现。复位原因、最小故障现场与健康监督相互关联，但断电丢失的RAM日志不等于持久化证据。

## 参数与 Flash

沿“候选参数 → 校验 → 生效 → 保存请求 → 写入结果 → 启动读取”追踪结果消费者，区分入队成功、处理完成、写成功与掉电可恢复。

核查 Magic、格式Version、稳定的序列化、长度、CRC、业务Range及缺省策略。结构体直接落盘或 `memcmp` 时，要检查布局、填充、大小端和版本演进；CRC正确不能证明业务参数合理，浮点比较要单独拒绝NaN/Inf。

读回比较能发现当前写入差异，不能单独保证掉电更新安全。A/B设计要检查独立擦除区域、序列比较、提交标记、写入次序、启动选择、旧格式迁移和擦写寿命。在任何更新阶段中断后，应按产品契约恢复完整旧配置、完整新配置或明确的安全缺省值。

## 状态机、滤波与恢复

审阅状态进入/退出动作、非法事件、default处理、状态超时、反馈复核及故障锁存。状态枚举存在不等于状态转移合法。

去抖、滤波、回差和重试的窗口会增加检测时间，按故障后果与期限选择。教程“连续失败3次”、8点平均或指数退避不能直接用于所有保护。旧值继续使用也需要最大年龄和失败策略。

恢复应限定次数、时间、退避与复核，并与外设所有者协调。非关键遥测失败能否降级须由产品安全条件决定；恢复通信/传感器不自动授权恢复危险输出或重新上电。

接口返回值统一可分阶段进行，不必为了一个 `Result_t` 重写全工程。保留可用于诊断和处置的错误信息及已有对外协议。
